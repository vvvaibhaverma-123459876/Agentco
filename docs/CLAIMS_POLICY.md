# Claims Policy

Agentco uses shipped-claim discipline for all product, architecture, and launch-readiness language.

## Shipped Definition

A feature is "shipped" only if all of the following are true:

- It has executable code.
- It has tests.
- The tests were run and passed in the relevant environment.
- It has documentation.
- It is present in main.

## Status Labels

- Shipped: meets the shipped definition.
- Partially Implemented: executable pieces exist but coverage, hardening, API integration, or operational proof is incomplete.
- Experimental: useful but not production-grade and not relied on for authority or trust.
- Future: planned or designed but not implemented as production code.
- Historical / Deprecated: retained for context but not current product truth.

## Forbidden Shipped Claims

Do not claim that Society, Civilization, a civilization OS, a fully autonomous company, or 29 AI employees are production shipped unless the capability matrix and current tests prove it.

## Calibration Rule

No unresolved, disputed, self-certified, circularly verified, post-hoc, or non-independent claim may increase trust, reputation, authority, jurisdiction, budget, or governance power.
